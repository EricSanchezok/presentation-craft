# 视觉解释（参考）

## 先选关系，再选表现

| 要解释的内容 | 合适的视觉 | 关键检查 |
|---|---|---|
| 差异、取舍 | 同尺度并排比较、哑铃图、对齐条形图 | 比较条件一致，标签靠近对象 |
| 流程与反馈 | 流程图、泳道、带状态的回路 | 方向正确，输入经过真正处理它的节点 |
| 组成与边界 | 分组结构图、分层剖面 | 包含关系与连接关系不混淆 |
| 随时间变化 | 时间线、折线、前后对照 | 时间尺度、事件顺序、基线明确 |
| 数量与不确定性 | 标准图表、范围带、样本点 | 单位、样本、区间含义、来源可见 |
| 人物或实物 | 真实照片、局部放大、标注 | 来源、裁切和情绪语义合适 |
| 概念转变 | 保持对象身份的状态变化 | 改变的是哪个条件及其结果 |

每张示意图先写图例语义：对象代表什么，连线表示数据、因果还是依赖，颜色对应什么变量，面积是否表达数量。没有数量依据时避免有比例暗示的分块图。参考性的性能曲线应标注“假设／示意，非实测”，不要伪造坐标、误差条或漂亮的数据点。

## 图形实现选择

SVG 适合可编辑的机制、路径、坐标图和标注，DOM 适合正文及需要自然换行的文本。复杂数据可用标准绘图库，但检查默认坐标、排序、图例与导出效果。Canvas／WebGL 只在对象量或交互确实需要时引入，并提供可阅读的静态替代。

照片和插画承担情境、真实对象或空间结构的说明任务。文生图适合概念插画、背景或难以获得的非证据性视觉；不生成冒充真实人物、实验结果、产品截图或新闻现场的材料。图中的精确文字、箭头、公式和数量标记用 SVG／DOM 叠加，避免把全部信息烘焙进位图。

没有适合的图片时可以用好图示，也可以用有意设计的文字页；不要为了满足“每页有图”而增加装饰。

## 连接与标注

连线应连接对象边界，路径为标签与主体留出空间。反馈回路可以外绕，避免所有箭头挤在中间。多种方向同时出现时，采用分层揭示或有含义的线型，而非增加颜色数量。

直接标注优先于远处图例；重要标签不能压在线、数据点或交叠图层上。主次线宽体现关注顺序，不代替关系语义。缩略图检查整体结构，放大检查端点、遮挡与文字。

## 素材记录

记录来源、作者／机构、使用条件、处理方式（裁切、翻译、重绘、生成）及其在演示中的用途。来源公开不等于有开放许可。品牌参考提供视觉约束，不会自动授权把品牌素材分发为通用模板。

## 从对象构建丰富场景

视觉丰富度来自足够的解释线索。先选物体与关系，保留轮廓、相关内部结构、状态标记和稳定参照，再构成场景。图标帮助识别，场景解释协作，图表承担数量比较；不要把其中一种当作所有页面的答案。

在分镜中标出哪些细节必需、哪些可以省略。例如材料附件说明为什么申请被退回，耳罩开口说明声音在何处到达耳边，镜片与固定感光面解释焦点移动。每个新增细节都应降低理解成本。具体流程与可运行示例见 [视觉设计案例](visual-decisions.md)。
