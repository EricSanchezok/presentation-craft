# 视觉解释

## 从信息关系选形式

先指出这一页要让观众看见的关系或体验，再选载体。同一主题可以同时需要数据图、照片、公式或文字；不要从现成组件反推内容。

| 需要呈现的内容 | 可选形式 | 需要明确的语义 |
|---|---|---|
| 差异与取舍 | 对齐比较、表格、哑铃图、并列画面 | 比较标准、基线和条件 |
| 数量与不确定性 | 条形图、折线、散点、分布、范围带 | 单位、尺度、样本和区间含义 |
| 组成、依赖与反馈 | 分组图、剖面、网络、泳道、闭环 | 包含关系、连接类型和方向 |
| 过程或时间变化 | 连续状态、时间线、前后对照 | 保持什么不变，改变什么，先后是否具有因果含义 |
| 空间与位置 | 地图、平面图、空间示意 | 方向、距离、层次与参考位置 |
| 推导、规则或算法 | 公式、代码片段、状态表、执行轨迹 | 当前条件、合法变换和中间结果 |
| 产品或操作体验 | 真实截图、局部放大、交互演示 | 用户目标、关键动作和可见反馈 |
| 人物、环境与氛围 | 照片、插画、图像序列 | 视角、情境、真实性与所需感受 |
| 主张、引文或转折 | 文字构图、留白、单一视觉锚点 | 阅读重点和上下文 |

## 编码关系

明确位置、颜色、大小、线型和标注分别代表什么。用共同尺度支持比较，用邻近和分组表达归属，用连接线表达确实存在的关系。没有数量含义的面积或颜色不要暗示测量精度。

数据图优先保证比较有效、单位清楚和来源可追溯。非零基线、不同分母、缺失值或不确定性会影响判断时，显式说明。定性曲线标为示意；不要用精致坐标、误差条或数据点把假设包装成实测。

直接标注放在对象附近，避开数据和路径。线端连接正确边界，为分支、回路及其标签分配空间。多类关系难以同时阅读时，调整层级或分步揭示。

## 构建有解释力的对象与场景

需要解释实物时，保留可识别轮廓与相关内部结构；需要解释抽象概念时，使用有稳定含义的节点、区域、符号或状态。先定义对象、关系、固定参照和变化变量，再安排空间。

按信息需求增加细节：形状帮助识别，内部结构解释作用，局部标记表示状态，环境提供上下文。图标适合提示局部含义；机制场景需要展示对象之间怎样协作。矩形适合抽象分组，实物图适合真实结构，不以绘制元素数量衡量丰富度。

检查新增细节是否带来识别、解释、情境或情绪上的价值。主图过于空泛时补充必要线索；层次难以分辨时减少与当前任务无关的细节。具体选择练习见 [表达选择与迁移](visual-decisions.md)。

## 选择实现载体与素材

使用 SVG 绘制可编辑路径、结构和标注，DOM 承载需要自然排版的正文，合适的排版或渲染工具处理公式与代码。复杂数据可用绘图库，检查默认排序、坐标和导出效果；大量对象或连续交互确有需要时再使用 Canvas／WebGL，并设计静态替代。

需要真实证据或身份时选用有来源的照片、截图；需要概念、情境或视觉氛围时可使用原创插画或生成图像。用 SVG／DOM 叠加精确文字、数量与标注。记录素材来源、作者、许可和加工方式；引用网页不等于获得图片分发许可，生成或重绘的内容也不能冒充测量或真实事件记录。
