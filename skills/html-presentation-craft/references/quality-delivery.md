# 质量与交付（参考）

## 证据层次

- **实现存在**：源码中有相应分支，尚未证明运行结果。
- **结构检查**：类型、素材清单、引用和构建等静态或打包检查通过。
- **实际运行**：记录环境、入口、操作和可观察结果。
- **视觉与内容评审**：记录理解、重心、准确性和节奏的判断，以及修正依据。

不要把 HTTP 下成功播放写成双击文件验证，把打印 DOM 数量写成已检查 PDF，把无溢出写成设计优秀。受工具限制时准确注明；不能绕过工具拒绝来获得验证结论。

## 制作验收

1. 内容：主张与证据相符，引文可追溯，示意／假设清楚；标题、图与讲稿不矛盾。
2. 叙事：讲完能够说出观众带走的判断，换页有自然连接，类比无需额外学习。
3. 视觉：检查全套缩略图和各关键状态，重心、阅读路径、换行、图形关系、线端、标签与照片裁切成立。
4. 播放：遍历全部步骤的前进、后退、直接跳入和快速打断；检查总览、讲稿、计时、全屏、深链接和控制台。
5. 环境：默认 1920×1080、1280×720，加一个较小窗口；按真实场地增加必要尺寸。检查键盘焦点、减少动态效果和实际打印输出。
6. 排练：计时朗读并给观察图留时间。说明是朗读验证还是仅文本估算。

## 离线与资产

构建单文件后检查没有运行所需的外链脚本、样式、字体、图片、动态模块或数据请求。普通来源超链接允许联网打开，不属于播放依赖。大视频或在线产品 demo 必须事先约定交付方式，不能默默输出依赖网络的“离线包”。

在允许的浏览器环境实际双击最终文件、断网、刷新、导航并检查素材。若环境不允许 file 协议，记录限制，继续完成允许的结构与浏览器检查，不宣称双击已验证。检查打包文件与验收版本相同，解压到新目录复核入口和资源。

## 接收者体验

交付目录首层使用清楚的 `演示.html`。同时给讲稿、开始使用、素材来源、验证记录；按要求提供源码。开始使用明确“解压后双击哪个文件”、快捷键、全屏方式及实际已知限制。避免多个名为 final／latest 的版本。源码不带 node_modules、缓存、个人路径或服务端凭据。

## 修改的验收范围

文案小改检查内容、换行与字体覆盖；调整结构检查受影响的全部状态；改播放或打包逻辑运行相应行为检查。已有检查通过后，除非有新修改或未解决的疑虑，不反复扩大同一种验证。
