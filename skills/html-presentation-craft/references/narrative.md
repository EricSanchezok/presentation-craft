# 任务与叙事（参考）

## 简报与主张

先写一句“这场演示结束后，谁应当理解／相信／决定什么”。材料多不等于都应进入舞台：按支撑主张、必要前提、辅助细节分层。现场演讲的细节放入讲稿，独立阅读版需要在页面补足因果连接，教学需要给思考与练习留时间。

建立简短事实清单，区分可核实的事实、解释性推断、待检验假设、预期目标。重要引言核查原文、作者、日期与上下文；翻译和转述要标明。名人只能提供思想背景，不能替作者证明自己的方案。

## 结构选择

| 场景 | 常见有效路径 | 需要防止 |
|---|---|---|
| 学术猜想 | 矛盾 → 主张 → 机制 → 可证伪的实验 → 意义 | 把猜想写成结果；大量术语先于问题 |
| 研究结果 | 问题 → 方法选择 → 证据 → 边界与贡献 | 用研究过程时间顺序淹没主要发现 |
| 商业决策 | 决策问题 → 比较依据 → 推荐 → 风险与下一步 | 只有漂亮数字，没有支持决定的比较 |
| 路演 | 未满足需求 → 解决机制 → 证据 → 机会与诉求 | 用市场规模掩盖缺少需求或验证 |
| 教学 | 已知直觉 → 新问题 → 演示 → 预测／练习 → 迁移 | 没有前提铺垫；动画结束前不给思考时间 |
| 产品介绍 | 真实任务 → 关键体验 → 原理或证据 → 使用路径 | 功能清单代替用户价值 |
| 工作汇报 | 目标 → 变化与原因 → 偏差 → 决策／资源需求 | 罗列活动而不说明进展与影响 |

这是可选组织方式；题材、已有结构和用户要求优先。纯叙事演讲不必套研究论证，五分钟也不必固定七页。

## 分镜契约

用表或简短段落记录每页：角色、观众带走的理解、画面、步骤、讲稿、用时、出处。相邻两页应当能用一句因果或问题连接起来。不能连接时，检查是否缺前提、跳了层级或存在无关材料。

每个步骤描述观众新理解的关系，例如“故障节点被隔离，但其余请求继续通过”，而不是只写“左边框淡出”。已有标题、图与讲稿必须表达同一个观点。

## 专业、自信与自然

专业术语在精确而有用时保留，首次出现只解释理解所需的部分。不要用模糊代称替代已确立概念。主张使用主动、明确的句子；条件和边界尽量放在最相关的位置，避免每句都加试探性词语。

减少机械重复的主语与口号。比较“我们选择创新转化这一项”与“把这项发现转化成可以验证的产品能力”：后者更像演讲，前者更像填写表格。语言必须忠于具体场景，不能普遍替作者制造使命宣言。

类比优先选择受众熟悉、无需额外解释的情境。列出类比能说明和不能说明的部分，随后回到真实机制。不能从“人类学习方法更有用”直接推出某个模型架构必然有效。

## 时长与排练

用时预算应包含停顿、切换、观众观察图和可能的互动。字数只能粗估，最终通过计时朗读校准。超时时先删掉不支撑主张的分支，再重写句子；不以加快语速或缩小字体解决。讲稿包含承上启下的句子，屏幕保留可感知的重点。
