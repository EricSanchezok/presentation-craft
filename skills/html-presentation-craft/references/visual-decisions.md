# 表达选择与迁移

需要检验选型或借鉴案例时，先抽取理解任务与信息关系，再匹配表达方式。相似主题未必需要相同版式，不同主题也可能复用同一种关系表达。

## 按问题作出选择

| 当前问题 | 推导设计 | 检查是否成立 |
|---|---|---|
| 哪个方案更合适？ | 确定共同标准，再选择表格、对齐图表或并列证据；保留影响推荐的权衡 | 观众能否追溯推荐依据，而不是只看到一个高亮选项 |
| 多个环节怎样协作？ | 定义参与者、输入输出与边界，再选择结构、泳道或状态场景 | 连线是否表达真实关系，顺序是否与机制一致 |
| 什么发生了变化？ | 确定基线与变化变量，选择前后对照、时间线或连续状态 | 对象身份与比较条件是否稳定，是否误把先后当成因果 |
| 怎样从前提得到结果？ | 显示当前条件与关键变换，按需要使用公式、代码、图形或状态表 | 每一步是否有可解释依据，静态版能否保留必要过程 |
| 产品如何完成任务？ | 围绕用户目标选择真实界面与关键操作，用局部放大或标注减少搜索 | 能否看见操作反馈，是否保留足以理解界面的上下文 |
| 怎样建立情境与感受？ | 选择视角、细节和图文节奏，用画面与语言形成呼应 | 观众是否进入所需情境，视觉是否忠于内容与语气 |

这些判断可以组合。例如，同一场产品发布可以用照片建立情境、用截图展示体验、用数据支持价值，再用简短文字收束。页面任务不同且同一形式难以完成时，组合合适的表达；需要连续比较或统一叙事视角时，保留相同形式。

## 从示例提取可复用部分

需要具体技法时查 [源码索引](../assets/examples/README.md)。只提取当前需要的部分，并区分三个层次：

- **方法**：如何确定固定参照、编码关系、控制密度或安排揭示。
- **实现**：可复用的状态管理、连接、标注、属性动画及静态分支。
- **主题选择**：具体对象、类比、颜色、页数与讲述内容；在新任务中重新决定。

复用关系图或动画前，明确新内容中对象、关系与状态的对应含义。若只能替换名词而不能解释几何、顺序或标注的含义，重新构图。需要展示公式、地图、人物或界面时，直接选择相应形式，无需把它改造成现成示例中的实物剖面或流程图。

## 反查设计依据

检查每项主要选择：它由受众、材料、观看条件或表达目的中的哪项要求产生？换一个主题后，仍可迁移的应是选择依据和实现能力；若答案只剩“示例里如此”，重新判断。
