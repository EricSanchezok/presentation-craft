# HTML Presentation Craft

根据受众、材料和表达目的设计 HTML 演示。先确定观众需要理解、判断、学会或感受到什么，再选择叙事、视觉和交互；页数、风格、图形与动画由当前任务推导。

## 确定工作范围

读取材料、现有演示、参考样式与用户约束。识别受众的已有认知、使用方式、时长、核心信息和交付条件。只询问无法从上下文确定、且会改变方向的信息。

- 新制作：确定表达目标，再组织内容、分镜、视觉和实现。
- 修改：定位问题所在层次，保留用户锁定的内容和有效设计。
- 评审：给出可见问题、理解上的影响与修改优先级；只在任务包含修改时实施。
- 打包：确认最终版本，按 [质量与交付](references/quality-delivery.md) 检查。

现场演讲按讲述节奏组织；独立阅读补足页面自身的解释；教学或讨论为预测、练习和分歧留出空间。中间产物按任务复杂度简化，无需逐阶段请求确认。

## 推导设计

1. **找到认知变化。** 确定观众当前知道什么、缺少什么，以及结束时应带走什么；据此取舍材料。
2. **安排理解顺序。** 把必要前提、观点、证据、体验和结论组织成可跟随的路径。根据内容决定先给结论、建立悬念、演示过程或展示变化。
3. **选择表达形式。** 明确每页的任务，再选择图表、照片、截图、结构图、时间线、公式、代码、文字或其组合。优先使用能揭示关键关系或建立所需体验的形式。
4. **建立视觉层级。** 确定阅读起点、相关信息的空间关系与整体视觉语言。用有用的图形细节增加识别与解释线索，让每页构图服务当前内容。
5. **设计时间状态。** 按理解、讲述或互动节奏安排必要的揭示、变化与停顿。定义各步保留、增加和改变的信息，协调对象、标注、路径及周围布局；每个停留点都应成立。
6. **用结果校验选择。** 检查页面、讲稿与步骤是否支持同一表达目标，事实与证据边界是否准确，实际画面是否易读，以及播放与交付是否可靠。

新建或重组页面时，保留一份轻量分镜：每页的表达任务、关键内容、主视觉及其含义、必要步骤；按用途补充讲稿、时长和来源。若无法说明某项设计怎样帮助观众，重新选择表达形式，或删去该项。

## 实现与交付

已有项目沿用其有效结构。新项目可使用包内 [starter](assets/starter/)；创建命令、运行接口与离线约束见 [HTML 实现](references/runtime.md)。底座的默认比例、组件和主题是实现起点，可根据交付场景调整。

交付明确的 HTML 入口及必要的讲稿、来源、使用说明和验证记录。报告实际完成的检查及限制；发布与全局安装按用户要求执行。
